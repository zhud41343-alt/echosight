# EchoSafe 可靠性状态机与音频调度设计（ECHOSAFE_DESIGN）

## 1. 核心设计目标
面向视障辅助感知场景，**误报“安全”比“暂不可用”危险得多**。EchoSafe 通过集中式状态机与失效保护（Fail-Safe）规则，确保在任何传感器、模型、权限、页面可见性或时效异常时，系统显式降级或阻断不可信输出。

## 2. 六状态定义（`src/engine/echoSafe.ts`）
- `IDLE`：未启动，`dataSource = 'none'`，`canTrustLivePerception = false`。
- `INITIALIZING`：正在申请摄像头/麦克风权限或加载端侧模型。
- `ACTIVE`：摄像头权限已授予、视频轨道处于 `live`、帧刷新未过期（`< 2500ms`）、端侧模型真实就绪、页面在前台、音频上下文运行中。
- `DEGRADED`：摄像头正常但存在部分能力失效（模型加载失败、连续推理失败 ≥ 3 次、单次推理超时 > 3500ms、推理结果过期 > 4500ms、或音频被挂起）。
- `UNAVAILABLE`：页面切入后台（`document.hidden`）、摄像头拒权/无设备、视频轨道断开、或视频帧停止更新。此时立即清空过期检测框并阻断实时描述。
- `DEMO`：明确隔离的模拟演示模式（仅用于「专业实验台」），绝不进入实时助行通道。

## 3. 并发与性能隔离
- **单并发推理锁（`SingleFlightRunner`）**：同一时刻最多运行一次 TensorFlow.js 推理，避免低算力手机出现异步队列堆积与延迟雪崩。
- **双指标分离监控（`RuntimeMetricsTracker`）**：严格分开测量前端视觉处理 FPS（`visionFps`）与端侧 AI 实际推理 FPS（`aiFps`）及 P95 延迟（`p95InferenceMs`），杜绝将渲染帧率混充推理帧率。

## 4. 统一语音与音频调度器（`src/engine/audioScheduler.ts`）
- **三级优先级**：`EMERGENCY (3)` > `USER_QUERY (2)` > `AMBIENT (1)`。
- **抢占与保护**：紧急状态提示与用户主动提问可抢占普通环境播报；普通环境播报绝不能打断正在进行的紧急或用户查询播报。
- **听觉减负**：默认采用「简洁语音优先」策略（不默认开启连续 3D 声波噪音），提供 4 种可选提示模式（简洁语音优先 / 低频空间提示 / 仅按需描述 / 实验性连续声场）。
